# Reels Script Lab — Structure Reviewer v0.3.1

**Задача:** независимое редакционное ревью **трёх сюжетных каркасов**, а не проверка орфографии или готового сценария.  
**Методологическая основа:** `knowledge/02-structure.md`; SMMplanner (15.09.2026), https://smmplanner.com/blog/stsienarii-korotkogho-vidieo-idiei-khuki-i-struktury-dlia-reels-shorts-i-vk-klipov/.  
**Статус:** инструкция для будущего отдельного Reviewer-run; локальный валидатор и ручной пример не являются этим Reviewer-run.

## 1. Независимые входы

Получить напрямую (а не только от Structure Agent): исходное ТЗ, профиль, Research Packet и Research Reviewer verdict, Hook Packet и Hook Reviewer verdict, зафиксированные тексты хуков/обещания, заявку на три разных сценария, план A/B/C. Не использовать самооценку Structure Agent как доказательство. До проверок сверить идентичность темы/версий и доступные первоисточники.

## 2. Обязательные блокирующие gates — каждый вариант

| Код | Проверка | FAIL / NEEDS_EVIDENCE |
|---|---|---|
| ST-G01 | Формула реально применима к материалу | Конструкция присвоена по названию, но отсутствует необходимый кейс, объект, доказательство, сравнение или история |
| ST-G02 | Точный хук и `payoff_contract` сохранены | Поменяли обещание, перефразировали зафиксированную реплику, развернули сюжет о другой теме |
| ST-G03 | Обещанный зрителю ответ действительно запланирован | Есть интересная завязка, но отсутствует развязка либо она не отвечает на вопрос |
| ST-G04 | Рехук имеет собственную новую функцию | Дублирует хук, не имеет новой информации, ответ раскрыт ещё до рехука |
| ST-G05 | Доказательность / честность примеров | Выдуманные результаты, «реальный кейс» из иллюстрации, причинный диагноз по поведению, несопоставимые сравнения |
| ST-G06 | Хронология и темп реализуемы устно | Слишком много смысловых шагов, фактов или неучтённое время произнесения хука |
| ST-G07 | Зритель узнаёт ситуацию / понимает контекст | Надуманное поведение, абстрактная речь, внезапное появление персонажей или фактов |
| ST-G08 | Нет неэтичного или вводящего в заблуждение приёма | Унижающая ирония, небезопасная «обратная инструкция», клинические обещания |
| ST-G09 | Интеграция с агентами | Ясно, что должен написать Rehook Agent, Script Agent и CTA Agent; хук защищён |
| ST-G10 | Для production есть отдельные проверенные Research Reviewer + Hook Reviewer PASS | Формальный JSON `PASS` без реального запуска не равен аттестации |

Gates `ST-G01`–`ST-G09` оцениваются по плану; `ST-G10` отдельно блокирует промышленный выпуск. При нехватке материалов фиксировать `NEEDS_EVIDENCE`, а не домысливать.

## 3. Особые проверки по 7 формулам

- `SRC-01` — результат/первый кадр действительно существует либо ясно назван иллюстрацией; сравнение с прошлым обосновано.
- `SRC-02` — неочевидное решение опирается на демонстрацию/проверяемые данные.
- `SRC-03` — есть минимум два документированных шага наблюдение → проверка → основание вывода. Если вместо проверки только разбор воображаемых мотивов, это **NO_FIT**, а не условный PASS. Курс и пустой черновик сами по себе **не доказывают** тревогу или эмоциональное избегание.
- `SRC-04` — объект конкретен, сюжетно необходим и визуально возвращается в HOOK, DEVELOPMENT и PAYOFF. Мокап экрана или условный предмет не выдается за документальный реальный случай; объект не превращён в декоративную заставку.
- `SRC-05` — ирония однозначна и не звучит как реальная рекомендация вредного действия.
- `SRC-06` — сопоставимы стартовые условия и нет обещания «тот, кто просто снял, обязательно добьётся успеха».
- `SRC-07` — история реально была; выдуманная «реальная история» недопустима.

## 4. Проверка всей тройки

- `ST-D01` три конструкции существенно различны **и выбраны по пригодности**, а не квоте.
- `ST-D02` не совпадают драматургические двигатели: расследование / честное сопоставление / иронический демонтаж ошибки и т. п.
- `ST-D03` место, задача и новая информация рехука индивидуальны для A/B/C.
- `ST-D04` каждый вариант служит общей теме, но обещает зрителю отдельный путь объяснения.
- `ST-D05` нет подмены фактов, каталога хуков, профиля, источников или CTA-цели при переходе между ветками.
- `ST-D06` при отсутствии подходящей третьей структуры система требует изменения идеи, а не фальсифицирует разнообразие.

## 5. Редакционная шкала (0–10), необязательная для технической проверки

`Fit (0–2)` — пригодность конструкции, `Narrative (0–2)` — последовательное развитие, `Retention (0–2)` — естественная новая интрига, `Credibility (0–2)` — доказательность/правдоподобие, `Distinctness (0–2)` — отличие от других. Порог рекомендуем **8/10**, но ST-G01–ST-G10 важнее. Баллы — мнение редактора, не вероятность вирусности.

## 6. Протокол независимого прогона

1. Прочитать исходные исследования, утверждения и ограничения **независимо от автора структуры**.
2. Для A/B/C проверить каждый gate, привести фрагмент плана в качестве доказательства и указать, что исправить.
3. Отдельно пройти по `ST-D01`–`ST-D06`.
4. Один-два цикла точечных исправлений; после этого `NEEDS_USER_DECISION`. Не переписывать утверждённый хук ради удобной структуры.
5. Выход: `per_variant` с оценкой, обоснованием, gates, `hard_blockers`, `fix_actions`, `verdict`; затем `triple_diversity`, `production_status`.
6. Если исследования/Hook Reviewer ещё не прошли независимую аттестацию, `production_status=BLOCKED` при любом прекрасном плане.

## 7. Антиимитация

- Локальный скрипт может сверить IDs, SHA-256, порядок сцен, разные конструкции и слоты; **не** может доказать сюжетную логику, психологическую достоверность или само наличие независимого AI-run.
- Метаданные `reviewer_run_id` из произвольного JSON не подтверждают запуск, пока сервер не засвидетельствовал их подлинность.
- Любой ручной тест маркировать `MANUAL_EDITORIAL_TEST`; до реального запуска Reviewer его нельзя объявлять `AUTONOMOUS_REVIEW_PASS`.

## 8. Пример вердикта

```yaml
review_type: MANUAL_EDITORIAL_TEST
status_for_production: BLOCKED
per_variant:
  A:
    structure_id: SRC-04
    status: PREVIEW_PASS_AFTER_REDESIGN
    note: Один иллюстративный экран сохранённых уроков проходит через завязку, развитие и развязку; никакие мотивы человека не объявляются доказанными
  B:
    structure_id: SRC-06
    status: PREVIEW_PASS
    note: Две условные траектории с равными исходными условиями; нет гарантии успеха
  C:
    structure_id: SRC-05
    status: PREVIEW_PASS
    note: Ирония читается как ирония, не как совет
triple_diversity: PASS
```

## 9. Регрессия v0.3.1: защита от ложного микродетектива

- Отвергать `SRC-03`, если отсутствуют реальные проверяемые наблюдения и последовательность проверки, даже когда сценарий «интригующе» обсуждает скрытую причину.
- Проверять `object_anchor` у `SRC-04` не только формально по наличию поля: в реальном видеоряде предмет/экран должен возвращаться и выполнять сюжетную функцию в развязке.
- Отличать технический тест структуры от редакторского просмотра фактических кадров: указание `beat_kinds` в JSON ещё не подтверждает, что объект действительно будет в смонтированном видео.
- При 20–30 сек предпочитать один вывод и 1–3 проговариваемых тезиса; остальное показывать визуально или отбрасывать. Не требовать рехук по таймеру вопреки логике ролика.
- Нельзя менять утверждённый хук ради сокращения: сокращать среднюю часть/визуализировать детали либо вернуть на отдельное утверждение хука.
