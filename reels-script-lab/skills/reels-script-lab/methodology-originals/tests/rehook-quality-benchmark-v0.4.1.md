# Rehook Agent v0.4.1 — калибровочные отрицательные примеры

**Источник обратной связи:** пользователь отклонил предыдущую тройку Rehook Agent v0.4.0 как слабую; далее уточнил, что задача — изменить **агент**, а не вручную переписать три реплики. Этот документ — регрессионный набор для будущего независимого LLM Reviewer, а не новый сценарий.

| Ветка | Ранее выданный пример (негативный эталон) | Почему должен отклоняться в своём контексте |
|---|---|---|
| A | «А если прямо сейчас открыть камеру — на чём вы застрянете?» | Похож на упражнение/мини-CTA вместо неожиданного сюжетного поворота; вопрос сам по себе не добавляет новых наблюдений, а следующий бит можно объяснить и без реплики (`DISPOSABLE_REHOOK`, `NO_NEW_INFORMATION`, возможный `CTA_SUBSTITUTION`) |
| B | «А что, если первый вообще не тянет время?» | Неясное «первый» и слабое столкновение с предположением зрителя; без привязки к конкретному факту контраст остаётся декларацией (`NO_NEW_INFORMATION`, `GENERIC_SWAP`) |
| C | «И самое удобное — первый дубль пока никому не придётся показывать» | Скорее пояснение уже известной отсрочки, чем новый смысловой поворот; в контексте обратной инструкции не гарантирует необходимость следующей сцены (`DISPOSABLE_REHOOK`, `QUESTION_REPEATS_HOOK`) |

**Не распространять запрет на форму вопроса, на «А что, если», на «И самое интересное» и на тему откладывания вообще.** Мы проверяем _смысловую функцию в конкретной сцене_, а не набор запрещённых слов.

## Положительная калибровка свойств (без копирования текста)

- **Парадокс:** зритель считал, что откладывание — однозначно вредное или бессмысленное поведение; новый поворот заставляет задуматься о краткосрочной функции, но не выдаёт предположение за диагноз.
- **Открытый вопрос о скрытой выгоде:** появляется конкретный вопрос, на который следующий сюжет отвечает.
- **Неожиданная цена:** отсрочка приносит краткое облегчение, но удерживает человека от желаемого действия; цена должна быть объяснена по фактам, а не заявлена голословно.
- **Речь человека:** конкретно, коротко, с естественной паузой; никаких искусственных метафор и неподтверждённых универсальных утверждений.

## Приёмочный тест будущего runtime

1. На одном и том же Structure Packet дать генератору сделать 6–9 разных вариантов на ветку.
2. Отдельный Reviewer получает контекст и реплики без авторской самооценки.
3. Все три старых отрицательных эталона должны получить FAIL с предметной причиной, если представлены в тех же контекстах.
4. Reviewer должен отклонять даже формально корректный JSON, если не возникает нового зрительского вопроса.
5. Хотя бы один сильный кандидат **не гарантирован**: честный `NEEDS_REGENERATION` лучше плохого PASS.
6. Любое изменение источника/структуры требует пересмотра и не может выпускаться автоматически.

**Состояние теста на 20.10.2026:** набор создан, но отдельного runtime для слепого LLM-review пока нет. Нельзя заявлять, что тест творческого качества уже пройден.
