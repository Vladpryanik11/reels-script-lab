# Stage 04 — Structure Agent + Reviewer (restored)

**Полный обязательный регламент:** `references/13-structure-methodology.md` и `references/14-structure-reviewer.md`. Не заменять их упрощённым перечнем.

1. Сначала проверить пригодность каждого `SRC-01…SRC-07` под факты, аудиторию, первый кадр и реальный способ съёмки. Выдать `structure_id`, `fit_reason`, `excluded_structures`, `case_kind`, `narrative_route`, `reveal_map`, фактические основания, `beats` и специальные поля по виду драматургии. Если нет трёх содержательных маршрутов, вернуть в Hook Agent; никакой принудительной тройки.
2. **Hook ↔ Structure до lock**: показать Hook Reviewer как конструкция реализует `viewer_question` и `payoff_contract`; при несовместимости изменить конструкцию или запросить новую ветку Hook Agent. Никогда не переписывать зафиксированный автором текст молча.
3. Ветка не равна списку HOOK / DEVELOPMENT / REHOOK / PAYOFF / CTA. Для каждого бита требуется новое событие / доказательство / контраст / шаг расследования, визуальный ход и сохранённый до payoff смысловой зазор.
4. Structure Reviewer проводит отдельные проверки схемы и смысла. Локальный Python валидатор не способен подтвердить, что контраст честный или история настоящая, но не должен пропускать отсутствующие обязательные поля и подмену `SRC-*`.
5. Старые документы содержат архивные отраслевые примеры: это не настройки универсального ядра, другие профили не подключаются автоматически.
