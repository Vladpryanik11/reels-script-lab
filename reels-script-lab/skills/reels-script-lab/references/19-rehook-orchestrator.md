# ORCHESTRATOR — Rehook candidate selection v0.4.1

Оркестратор создаёт отдельный вызов Generator и отдельный **слепой** вызов Reviewer (не один и тот же вызов модели), передавая только контекст и анонимные кандидаты. Только Orchestrator хранит `generator_run_id`, `reviewer_run_id`, сопоставление candidate_id и реальную историю вызовов. Сгенерированные на месте строковые ID не являются доказательством независимости.

1. Проверь исходные Review-аттестации и версии пакетов; при отсутствии — только PREVIEW.
2. Запусти Rehook Generator 1 раз по каждой ветке (или одним запуском с тремя ветками), сохрани все 6–9 кандидатов/ветка и механизм TR.
3. Сформируй payload независимому Reviewer из: locked Hook, контекст прямо до реплики, реплика, следующий бит, payoff, допустимые факты. НЕ передавай объяснений Generator, его рангов и фаворитов; перемешай кандидатов.
4. Прикрепи ответы Reviewer с реально известным run_id, не позволяй Generator заполнять этот идентификатор.
5. Запусти `scripts/validate_rehook_selection.py`/логическую валидацию процесса. Это только контракт, не creative PASS.
6. Выбирай лучший исключительно среди PASS. Если их нет, передай список конкретных провалов Generator для новой попытки (максимум два цикла). Если честной интриги нет — к Structure Agent.
7. До финального Script Reviewer сохраняй кандидат только как `PREVIEW`; после написания сценария обязательно заново проверь склейку и payoff, даже если рехук отдельно понравился.
8. Пользователю показывай одну выбранную реплику на ветку и кратко «почему», а не весь набор из 27, если он специально его не запросил. По желанию показывай 2 лучших конкурента и причины отказа.

Избегай искусственной симметрии: у A/B/C три разные драматургические задачи, но не обязан использовать три разные техники Tatam.
