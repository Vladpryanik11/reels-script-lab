# Reels Script Lab — Rehook Reviewer v0.4.1

> **Восстановленная методология.** Текст основан на ранней утверждённой версии и не сокращён до общего перечня. Указанные примеры прежнего проекта — только иллюстрации; правила универсальны для всех отраслей. Полный первоначальный документ без адаптации сохранён в `methodology-originals/`. `SRC-*`/`TR-*` и проверочные поля — проектные ID, не цитаты источников.

**Назначение:** независимый семантический фильтр рехуков. Принципы техники: Tatam Digital, https://www.tatam.com/blog/hook-rehook-framework-for-influencer-briefing. Критерии below — собственные требования проекта. Это спецификация, не свидетельство независимого запуска.

## 1. Обязательная изоляция

Reviewer получает **для каждого кандидата**: полный Hook, контекст 1–2 реплик ДО, реальный следующий бит/кадр, план payoff, допустимые утверждения Research, профиль и сам текст рехука. НЕ получает `why_selected`, `new_question` автора, его оценки, список фаворитов и «прошло прошлое ревью». Порядок кандидатов перемешивает Orchestrator, не автор.

**Первое действие Reviewer:** после прочтения сцены и самого рехука самому назвать новый вопрос зрителя и новое наблюдение; только затем делать оценку. Авторские описания не засчитываются. Нельзя проверять изолированную «красивую» фразу без того, что ей предшествует и что идёт после.

## 2. Blocking gates (каждый кандидат)

| ID | Gate | FAIL, если |
|---|---|---|
| RH-R01 | Новое конкретное знание / точка напряжения | Реплика не добавляет информации, меняет лишь интонацию |
| RH-R02 | Новый вопрос зрителя | Reviewer без подсказки не может назвать вопрос, отличный от Hook |
| RH-R03 | Нужна следующая сцена | Реплика не создаёт обязательства раскрыть что-либо дальше; при удалении ничего не теряется |
| RH-R04 | Конкретика темы | Фразу без изменений можно поставить в любой ролик |
| RH-R05 | Не выдан ранний ответ | Смысл payoff уже раскрыт до/в рехуке |
| RH-R06 | Обеспечен payoff | Следующий бит действительно начинает раскрывать вопрос, а финал его разрешает |
| RH-R07 | Правдоподобие | Сцена, мотив, чувство или последствие придуманы как универсальная реальность |
| RH-R08 | Факты | Нет выдуманной статистики, исследований, диагнозов, фальшивой причинности |
| RH-R09 | Живая устная речь | Искусственный синтаксис, бессодержательная интрига, канцелярит, вопрос «для вопроса» |
| RH-R10 | Сохранён Hook / Structure | Нет семантического дубля и переписывания утверждённого материала |
| RH-R11 | Продолжительность и ритм | Реплика произносится неестественно быстро или ломает сцену |
| RH-R12 | Не подмена CTA | «Ответьте в комментариях» вместо сюжетной интриги |

Формулировки **не запрещаются по чёрному списку отдельных слов**. Выражение «И самое интересное...» иногда работает, если за ним следует действительно конкретный поворот. И наоборот, короткая «красиво звучащая» фраза может быть пустой, даже без ИИ-штампов.

## 3. Слепые испытания

Reviewer проводит пять испытаний из `references/15-rehook-methodology.md`: удалить реплику, пересадить в другой сюжет, вывести новый вопрос, доказать payoff, проверить склейку с соседними битами. Каждый провал требует `issue_code` и короткого объяснения со ссылкой на реальную часть сценария, а не общую оценку «слабо».

Рекомендуемые `issue_code`: `NO_NEW_INFORMATION`, `QUESTION_REPEATS_HOOK`, `DISPOSABLE_REHOOK`, `GENERIC_SWAP`, `PREMATURE_ANSWER`, `MISSING_NEXT_BEAT`, `SCENE_NOT_CREDIBLE`, `UNSUPPORTED_FACT`, `AI_SLOP`, `CTA_SUBSTITUTION`, `TIMING`, `UPSTREAM_CHANGED`.

## 4. Выбор между кандидатами

- Норма: 6–9 кандидатов на ветку, минимум три смысловых механизма; 3 ветки A/B/C могут иметь разные техники и повороты.
- Reviewer оценивает **все** варианты, а не только фаворита автора. `PASS` разрешён только при прохождении blocking gates.
- Если несколько PASS, предпочитать тот, где **узнаваемая конкретная ситуация + неожиданный честный поворот + обязательное продолжение** сильнее, без сверхобещаний. Пояснить отличие от ближайшего конкурента.
- Никакой шкалы 8/10 для условно слабой фразы. Можно показать редакторское сравнение, но PASS только при всех обязательных gates.
- Если все FAIL, вернуть `NEEDS_REGENERATION`; после двух циклов или при отсутствии честного поворота — `NEEDS_STRUCTURE_REVISION` / `NEEDS_USER_DECISION`. Не менять Hook.

## 5. Калибровочный набор

`tests/rehook-quality-benchmark-v0.4.1.md` включает три пользовательски отклонённых примера. После разработки реального runtime Reviewer должен прогнать их **вслепую** и выдать FAIL по указанным причинам. Это необходимый регрессионный тест, но он не гарантирует, что все будущие рехуки будут сильными. Положительные эталоны проверяют наличие открытой смысловой интриги без слепого копирования словесных формул.

## 6. Формат вердикта для каждого кандидата

```yaml
candidate_id: A-1
verdict: REJECT # PASS | REJECT
inferred_viewer_question: "" # вопрос, который Reviewer вывел сам; если не возник, пусто
specific_new_information: "" # не слова автора, а названный новый факт или наблюдение
next_beat_validation: "" # конкретно что покажет/расскажет следующая сцена
issues:
  - NO_NEW_INFORMATION
independent_reviewer_run_id: null # заполняется только реальным вызовом
```

Сначала получаем полный Blind Review для всех кандидатов, потом открываем `why_selected` автора и обсуждаем сравнение. Техническое заполнение этого YAML и декларативный `run_id` НЕ доказывают независимость; подтвердить её может лишь Orchestrator реальных запусков.

## 7. Ограничения и отчёт

Пока автономные роли не развернуты, Reviewer может проводить редакторский разбор, но **не вправе выставлять `PRODUCTION_PASS`**. Не обещать миллионы просмотров или конкретное удержание. После готового Script Agent повторить проверки RH-R03, RH-R05 и RH-R06 на полном тексте.
